During a downtime this problem sends no mail, not even "resolved". If it is still active when the downtime ends, you get a mail. If it is gone by then, nothing is sent.

A downtime covers exactly one problem: the same check, object and reason. A new reason or a new object name, such as a recreated pod, is a new problem and sends mail as usual. Only pvc-usage, cert-expiry and workload-replicas stay the same problem when the reason changes.
